\section{Problem Setting}
\label{sec:problem}

\paragraph{MDP formulation.} Slime Volleyball is a two-player game played to
five lives on each side. We treat it as a partially observed Markov decision
process $\mathcal{M} = (\mathcal{S}, \mathcal{A}, p, r, \gamma)$ from the
learner's (right) side:
\begin{itemize}
\item $\mathcal{S} \subset \mathbb{R}^{12}$. The observation is a fixed-order
  vector $[x, y, v_x, v_y]$ for the agent, the ball, and the opponent, each
  divided by a fixed scale factor of $10.0$ inside the environment. The
  observation is a 12-dim summary of an underlying continuous physics state
  --- there is no explicit history, so we are technically in a POMDP, but the
  velocity terms make the observation Markov enough that recurrent or stacked
  policies do not give a measurable lift on this task.
\item $\mathcal{A}$ is \textsc{Discrete}(6). The six discrete actions
  decompose into a binary 3-tuple
  \texttt{(forward, backward, jump)} via a fixed lookup
  $\textsf{ACTION\_TABLE}$, mirroring the original
  \texttt{MultiBinary(3)} action space.
\item $p(s' \mid s, a, a^{\text{opp}})$ is the slimevolley physics
  step. We use the two-player API
  \texttt{env.step(a, otherAction=}$a^{\text{opp}}$\texttt{)}; the
  opponent's action is drawn either from a frozen self-play snapshot or
  from the scripted baseline, depending on the self-play mixer.
\item $r(s, a) \in \{-1, 0, +1\}$. The reward is the agent's life delta
  per frame: $+1$ when the opponent loses a life, $-1$ when the agent
  loses one, $0$ otherwise. Episode return is therefore
  $\in [-5, +5]$, with $\pm 5$ meaning a sweep and $0$ a draw at the
  3000-frame time-cap.
\item $\gamma = 0.99$ for both DQN and PPO.
\end{itemize}

\paragraph{What is ``data'' here?} For DQN, training data is a
\textbf{replay buffer} of one-step or $n$-step transitions
$(s_t, a_t, R_t^{(n)}, s_{t+n}, d_t)$ collected from 16 parallel
\texttt{SubprocVecEnv} workers and uniformly sampled (or PER-prioritized
in the Rainbow variants). For PPO, data is an \textbf{on-policy
rollout} of length $T \times N = 256 \times 16 = 4096$ transitions
collected after every gradient update; once consumed it is discarded.

\paragraph{Data quality concerns.} Two RL-specific data issues drove
much of the experimental design.

\textbf{Opponent distribution shift.} In self-play, the opponent
distribution is non-stationary: today's snapshot pool was generated by
older policies that themselves trained against still-older policies.
Bootstrapped Q-targets are particularly exposed to this --- a learned
$Q(s, a)$ estimates ``the value of $s$ assuming $\pi_{\text{opp}}$
keeps acting like the snapshot it was estimated under.'' We mitigate
this with three knobs: a slow target network with $\tau{=}0.005$
Polyak averaging, a FIFO snapshot pool that bounds the staleness of
in-pool opponents, and a baseline-mixing parameter
$p_{\text{base}} \in [0, 1]$ that draws the scripted RNN baseline as
the opponent for a fraction of episodes (we vary
$p_{\text{base}} \in \{0, 0.4, 0.7\}$ and find $0$ catastrophic --- see
Section~\ref{sec:results}).

\textbf{Reward sparsity.} A 3000-frame episode contains at most ten
nonzero reward events (five lives per side). The credit assignment
horizon is large compared with the discount window: at $\gamma = 0.99$,
the bootstrapped value of a reward 100 frames away is attenuated by
$\sim 0.37$. $n$-step returns ($n{=}3$) push more of the gradient
signal into the actual rewards, but as we show empirically, they
\emph{require} the bias correction of Double DQN to be net-positive.
